# PetVerse · 智慧养宠社区平台

> 面向宠物爱好者的微服务社区平台，覆盖「虚拟宠物养成 + 真实宠物档案管理 + 社区社交 + 周边商城」四大业务域，并自研 AI 服务提供养宠顾问对话、健康智能评估、评论摘要与个性化推荐能力。

## 项目介绍

本项目基于微服务架构的宠物社区项目，采用 **Java + Python 混合微服务**：Java 侧包含网关、用户、宠物、动态（宠域空间）、社交、点赞评论通知、商城共 8 个服务；AI 能力独立为 Python（FastAPI）服务，注册进 Nacos 后由 Spring Cloud Gateway 统一路由（`/api/ai/**`），与 Java 体系共享网关鉴权与服务发现。

用户端核心业务围绕宠物主人展开：虚拟宠物签到养成（经验/等级）、真实宠物身份证与健康档案、宠域空间动态（可见性/热度榜）、好友与私聊、商家入驻与到店自提商城。AI 服务基于 **LangGraph 状态图编排**，为全站提供智能问答、健康评估、口碑总结与个性化推荐。

## 技术栈

Spring Boot、Spring Cloud、MyBatis-Plus、MySQL、Redis、RocketMQ、Elasticsearch、PostgreSQL + pgvector、**LangChain / LangGraph**、FastAPI、阿里云 OSS。

## 项目亮点

1. **独立设计实现 AI 对话编排引擎**：基于 LangGraph StateGraph 将「意图识别 → RAG 检索 / Agent 工具调用 → Prompt 组装 → 流式生成」编排为条件路由状态图，闲聊类意图自动跳过检索与工具节点以降低延迟与 token 消耗；Agent 通过 6 个工具（宠物档案 / 订单 / 购物车 / 商品搜索 / 评论 / 热门动态）查询用户真实数据作答；命中急症意图（中毒、抽搐、尿闭等）时强制注入「就医提示」安全护栏，防止 AI 越界替代兽医诊断。

2. **实现高可用的 SSE 流式对话链路**：自定义 `meta → delta → done` 事件协议，采用生产者-消费者模型 + 15s 心跳注释行防止网关/代理掐断长连接；全局信号量限流（20 路并发、3s 获取超时）实现过载保护；用户中途停止生成时问题与已产出的部分回复双路收尾——补写图状态记忆 + 条件写入消息表（会话已删则原子跳过），`asyncio.shield` 保证取消路径写入落地，避免内容丢失、记忆断裂与重复写入。

3. **基于 LangGraph 官方 checkpoint 实现可恢复的对话记忆**：图状态 messages 按「用户 + 会话」线程由官方 PostgresSaver 自动持久化到 PostgreSQL，跨轮自动恢复上下文；用户停止生成时通过 `aupdate_state` 把问题与已产出的部分回复（`interrupted` 标记）补写回图状态，被中断的轮次同样进入后续对话的记忆；针对流式写入与「删除会话」的竞态，用条件写入（会话表存在性检查）避免已删除历史被“复活”；在 Windows ProactorEventLoop 约束下用「官方同步引擎 + 线程池代理」实现跨平台一致（Linux 亦可直接运行）。

4. **实现 RAG 知识库双通路检索**：基于 pgvector + OpenAI 兼容 Embedding 实现语义检索（余弦相似度阈值过滤 + 带来源引用注入 Prompt，降低幻觉），内置疫苗/驱虫/喂养/常见病/行为训练五类知识语料，`RecursiveCharacterTextSplitter` 中文友好切分 + 幂等导入；Embedding 未配置或向量库故障时自动降级为字符 bigram 关键词检索，并设 60s 失败冷却避免故障期间反复重连。

5. **解决跨大模型厂商的结构化输出兼容问题**：不同服务商对 `json_schema` / `tool_choice` 支持差异极大（如 DeepSeek 思考模型两者均不支持，导致四类结构化任务**静默降级**为规则逻辑、接口仍返回 200 难以察觉），实现 `json_schema → function_calling → json_mode` 三级自动探测降级 + 可用方式进程级缓存，支撑意图识别、健康评估、评论摘要、推荐重排四个 LLM 结构化输出场景稳定运行。

6. **落地事件驱动的微服务基础设施**：基于 RocketMQ 解耦异步链路——动态/商品的 ES 索引异步同步（挂了自动重投）、订单超时延迟消息自动取消并回补库存、点赞计数异步落库 + 通知投递、商家审核通过后角色升级；Elasticsearch 故障时 60s 熔断窗口自动降级 MySQL 模糊查询保障可用性；网关统一 JWT 鉴权、剥离并重注入内部 `X-User-Id` 信任头，支撑 Java / Python 跨语言服务间的身份透传与越权防护。

## 附：面试可展开的细节索引

| 亮点 | 常见追问 | 回答要点 |
|---|---|---|
| 1 编排引擎 | 为什么用 LangGraph 而不是直接调模型 | 手写链路难以表达条件路由与多节点；状态图节点职责单一、可观测，`stream_mode="messages"` 只透传生成节点的 token 增量 |
| 2 SSE | 为什么不用 WebSocket / 轮询 | 单向推送场景 SSE 更轻；EventSource 不支持 POST 故用 fetch + ReadableStream 手动解析 |
| 3 记忆存储 | 为什么不直接用 LangGraph Checkpointer | 业务已有成熟的双写与删除语义；三级隔离（用户+宠物+会话）在关系库里更易维护 |
| 4 RAG | 检索不准怎么办 | 相似度阈值过滤 + TopK 限制 + 来源引用；关键词通路用覆盖率而非 Jaccard 打分（长文本不被稀释） |
| 5 结构化降级 | 怎么发现这个问题 | 推荐理由全是模板文案才暴露；接口 200 但内容是规则兜底，属于"静默降级"，必须靠结果内容巡检发现 |
| 6 事件驱动 | 消息丢失/重复怎么办 | 生产端 MqEventPublisher 抽象 + 消费端 MqDeduplicator 去重；ES 索引可由 DB 重建 |
