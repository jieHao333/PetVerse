# PetVerse 后端开发规范

本规范约定了 PetVerse 微服务项目的代码组织与实体类规则。

## 1. 模块职责

| 模块 | 职责 |
|---|---|
| petverse-common | 所有实体类（DO / DTO / VO）、统一返回、异常处理、通用配置、工具类 |
| pet-service | 宠物业务：controller / service / mapper（无实体类） |
| note-service | 笔记业务：controller / service / mapper（无实体类） |
| gateway-service | 网关，仅负责路由转发与跨域 |

**核心约定：所有实体类（数据库实体 DO、请求实体 DTO、返回实体 VO）一律放在 `petverse-common`，业务模块禁止新建实体类。**

## 2. 包结构规范

```
com.my.petverse.common
├── entity/                 # DO 数据库实体（对应数据库表）
│   ├── BaseEntity.java     # 实体基类
│   ├── pet/                # 宠物域实体
│   └── note/               # 笔记域实体
├── dto/                    # 请求实体（入参）
│   ├── base/               # 请求基类（如 BasePageQuery）
│   ├── pet/
│   └── note/
├── vo/                     # 返回实体（出参）
│   ├── pet/
│   └── note/
├── result/                 # 统一返回：Result、ResultCode、PageResult
├── exception/              # BusinessException、GlobalExceptionHandler
├── enums/                  # 通用枚举（如 PetClaimMethod、PetRarity）
├── util/                   # 通用领域工具（如 PetLevelCalculator 等级经验计算）
└── config/                 # 通用配置（MyMetaObjectHandler、MybatisPlusConfig）
```

规则：
- DO / DTO / VO 按业务域分子包，避免不同服务出现同名类冲突。
- 基类统一放 `entity` / `dto/base`，不放业务包。
- 业务模块中的类统一命名格式为 `com.my.petverse.<模块>.<分层>`。

## 3. 命名规范

| 类别 | 后缀 | 示例 | 说明 |
|---|---|---|---|
| 数据库实体（DO） | 无 | `Pet`、`Note` | 通过 `@TableName` 映射表 |
| 新增请求 | `SaveDTO` | `PetSaveDTO` | 不允许包含 id |
| 修改请求 | `UpdateDTO` | `PetUpdateDTO` | 必须包含 id |
| 条件查询 | `QueryDTO` | `PetQueryDTO` | 按需创建 |
| 分页查询 | `PageQueryDTO` | `PetPageQueryDTO` | 继承 `BasePageQuery` |
| 返回实体 | `VO` | `PetVO` | 字段按前端需求裁剪 |
| 分页基类 | `BasePageQuery` | `dto/base/BasePageQuery.java` | 含 pageNum/pageSize |
| 分页返回 | `PageResult<T>` | `result/PageResult.java` | 统一分页出参包装 |

## 4. 实体类规则

### 4.1 DO（数据库实体）
- 命名：不带后缀，如 `Pet`。
- 必须继承 `BaseEntity`（含 `id`、`createTime`、`updateTime`、`deleted` 逻辑删除）。
- 必须标注 `@TableName("表名")`、`@Data`、`@EqualsAndHashCode(callSuper = true)`。
- 字段使用驼峰命名，由 MyBatis-Plus 自动映射下划线列名。
- 非表字段必须标注 `@TableField(exist = false)`。
- 禁止在 DO 上添加校验注解。

### 4.2 DTO（请求实体）
- 命名：见命名规范表。
- `implements Serializable` 并声明 `serialVersionUID`。
- 使用 jakarta.validation 校验注解（`@NotBlank`、`@NotNull`、`@Size`、`@Min`、`@Max` 等）。
- 禁止继承 DO、禁止出现 MyBatis-Plus 注解。
- Controller 入参使用 `@Valid` 触发校验，异常由 `GlobalExceptionHandler` 统一处理。

### 4.3 VO（返回实体）
- 命名：`<实体名>VO`。
- `implements Serializable` 并声明 `serialVersionUID`。
- 不加校验注解。
- 禁止直接返回 DO，字段按前端需求裁剪，不暴露内部字段（如 `deleted`）。
- 分页返回统一使用 `PageResult<T>`。

## 5. 分层调用规范

```
Controller → 只接收 DTO，只返回 Result<VO> / Result<PageResult<VO>>
Service    → 业务逻辑 + DO/DTO/VO 转换
Mapper     → 只操作 DO
```

- 禁止 DO 越过 Service 直接到达 Controller。
- DO/DTO/VO 转换放在 Service 实现类中（私有 `toVO` 等方法），条件复杂时再抽取独立转换器。
- 禁止跨层传参、禁止在 Controller 内拼装 SQL 条件。

## 6. 表结构规范

- 每个业务服务使用独立数据库（如 `petverse_pet`、`petverse_note`）。
- 公共字段：
  - `id`：BIGINT，雪花算法主键
  - `create_time`：DATETIME，插入自动填充
  - `update_time`：DATETIME，插入/更新自动填充
  - `deleted`：TINYINT，逻辑删除（0 未删除 / 1 已删除），全局自动生效
- 表名：单数小写、下划线分隔。
- 建表 SQL 存放于各服务 `src/main/resources/db/schema.sql`。

## 7. 代码规范

- 代码必须要有注释具体可参考以写过的代码 (如 `/** 根据ID查询宠物 */`)。
